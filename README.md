# 灯火阑珊 · Lamplight

> 给 AI 的单轮任务装一道收敛闸：该提醒时提醒，该拦住时拦住，并明确告诉它「现在该交付什么」。

名字取自「蓦然回首，那人却在灯火阑珊处」——热闹（疯狂调工具）散去的地方，才看得见人。硬拦发生后，AI 停下工具调用，回头把进度说清楚，而不是继续往前冲。

这是一个 [Operit](https://github.com/fengyu-12) 的 ToolPkg 插件，包 ID `com.nyan.turn_guard`。

---

## 它解决什么

AI 干长活会跑偏：同一个工具反复调、同一个错反复撞、一轮几十次调用还在原地打转。
本插件挂在工具生命周期钩子上做计数与判定，用八个可调阈值把「继续尝试」和「该收尾了」分开。

| 信号 | 默认值 | 触发后 |
|---|---|---|
| 调用次数 | 8 次 | 注入一次提醒 |
| 提醒时长 | 本轮 5 分钟 | 注入一次提醒 |
| 相同调用 | 同工具同参数连续 3 次 | **拦截本次调用** |
| 相同失败 | 同工具同参数连续失败 3 次 | 注入一次提醒 |
| 硬阈值 | 50 次调用 | **拦截本次调用** |
| 硬停时长 | 15 分钟 | **拦截本次调用** |
| 空闲重置 | 80 秒 | 无在途工具且静默严格超过，仅重置调用、重复与失败计数 |
| 活动断档 | 10 分钟 | 无在途工具且静默严格超过两种重置阈值的较大值，重开活动轮次 |

判定分两层，互不干扰：软阈值负责「提个醒」，硬阈值负责「按停」。

### 三条提醒，按原因分开

动作只有一个：**说一句话**。没有选项、没有裁决负担，而且「未报告则停止工具调用」是可检查的违例。

| 类型 | 原文 |
|---|---|
| 调用较多 | `调用较多：先向用户报告一句当前进度（已确认什么、还在查什么）；未报告则停止工具调用，不要静默继续。` |
| 本轮耗时较久 | `本轮耗时较久：先向用户报告一句当前进展；未报告则停止工具调用，不要静默继续。` |
| 同工具同参数连续失败 | `同工具同参数连续失败：向用户报告一句失败原因并停止工具调用；原因不明就说尚未查明，不要静默继续。` |

时间采用独立墙钟起点 `activeSince`（当前活动首个事件），生命周期事件与 prompt 都检查软阈值，prompt 负责送达；硬拦只在 intercept 检查。没有事件时不主动唤醒或中止工具，长工具返回后提醒，后续 intercept 才硬拦。

计数窗口 `windowStart` 与活动时长解耦：60 秒空闲也计入墙钟；严格超过 80 秒可清计数，却不清活动起点、一次提醒额度或收尾标志。在途请求直到 result/error/finished 保留两个窗口，长工具超过 15 分钟也不会重开时间预算。无在途调用且距上次生命周期或 prompt 事件严格超过 `max(idleResetMs, activeResetMs)` 才开始新活动轮次；恰好达到不重置。切换 chat 仍重建状态。

`activeResetMs` 默认 600000 毫秒，可在设置页「活动断档」或配置工具中修改；缺少宿主 turn id，因此这是区分长思考与真实离开的启发式。计时包括工具耗时、思考及短暂空闲，不等于 CPU 时间。三类软提醒共享一次额度，优先级 calls > errors > time。`softMs=0` 只关闭时长软提醒，不关闭次数、失败提醒或时间硬拦。

原因不同，给的出路也不同。不会把「方法错了」说成「调得太多」。

### 一轮怎么算

插件监听 `message_persisted`：**用户发来新消息即新一轮**，计数与提醒额度清零；AI 自己的回复算「本轮达成」，不清零。`lastSender` 记进 status（宿主给什么就记什么，实测值为 `user`），未知值只记录、不猜测。

没有宿主 turn id，「一轮」的边界就是靠这条事件推断的。

### 常驻收敛规则（system prompt 层）

0.9.0 起改走 `registerSystemPromptComposeHook`：插件把收敛规则**拼进 system prompt**，每轮请求都在。
与 0.8.x 的 `advice` 路线不同，**不需要在会话里激活包**，注册即生效。

规则里的阈值是**实时读配置**的（0.9.1 起），改完设置下一轮就跟着变：

> 交付前先说明：已确认什么、还缺什么。连续工具调用超过 8 次，先给用户一句当前进度再继续。同一工具同参数连续失败 3 次：换一次实质不同的做法；换不了就报告阻塞。用户发来新消息即视为新一轮，重新计数。

（上面用 `8` 举例，实际渲染的是你设置里的当前值。）

两个开关**互相独立**：

| 开关 | 字段 | 默认 | 管什么 |
|---|---|---|---|
| 常驻收敛规则 | `adviceEnabled` | 开 | 写进 system prompt，每轮都在 |
| 接近阈值时提醒 | `warn` | 开 | 到阈值时往工具提示注入一句 |

关掉常驻开关后只剩触发式提醒与硬拦；关掉触发式提醒，常驻规则照样在。

**实测**（2026-11-16）：把软阈值改成 2 后重启 app、开新会话，模型首轮「思考过程」里即引用「规则说达到 2 次先给进度」并按规则报进度 —— 说明常驻层真的进了上下文，且读到的是实时值而非硬编码的 8。

### 拦住之后还给一条收尾指令

硬拦发生后，下一次请求会再注入一条：说明已验证结果、未完成项、阻塞及可行下一步；不要再调用工具，不得伪称完成。

拦截只负责停下，这条负责让它**说清楚停在哪**。

**方式一：插件市场**（若已上架）

**方式二：手动导入**

1. 把 `.toolpkg` 放进 Operit 的 `extensions/device/packages/` 目录
2. 用 operit_editor 执行 `package import <VFS 绝对路径>`，例如 `/virtual/android/sdcard/Download/<包名>.toolpkg`，再 `package enable turn_guard`。注意：`/sdcard/...` 会被重写成别的路径、`/operitapp/...` 会报 Cannot access，只有 `/virtual/android/sdcard/...` 可用。
3. 或直接在 App 的「包管理」里导入

## 使用

打开插件的设置页，八个步进器（支持直接输入数字，保留 ± 微调）：

```
调用额度
  空闲重置       80 秒    无在途工具且静默严格超过，仅清计数
  活动断档       10 分钟   无在途且静默超过两种重置阈值的较大值，重开活动轮次
  软阈值          8 次     本轮累计调用达到该次数，注入一次提醒
  提醒时长        5 分钟   从活动首个事件计时；0 关闭时长提醒
  硬阈值         50 次     本轮累计调用达到该次数，拒绝后续工具调用
  硬停时长       15 分钟   从活动首个事件计时，到时拒绝工具调用

重复检测
  相同调用        3 次     同一工具、同一参数连续出现多少次，判定为原地打转
  相同失败        3 次     同一工具、同一参数连续报错多少次，判定当前做法没有进展
```

保存后立即生效，**不用重装，也不用重启 app**。另有三个开关：达到上限时是否拦截、常驻收敛规则、接近阈值时是否提醒。

日志：单文件 `turn_guard-timeline.jsonl`，只记触发事件（提醒 / 拦截），覆盖写、最多留 5 条。

## 开发

要求 Node.js ≥ 18、TypeScript 5.x、Python 3（打包用）。

```bash
# 1. 编译（src/*.ts → dist/*.js）
node /usr/local/lib/node_modules/typescript/bin/tsc -p tsconfig.json

# 2. 跑测试（七套，零依赖）
node test/test-v0.6.6.cjs
node test/test-v0.6.cjs
node test/test-v0.6.2.cjs
node test/test-v0.5-config.cjs
node test/test-v0.4.cjs
node test/test-v0.7.cjs
node test/test-v0.8.cjs

# 3. 打包
python3 tools/pack_toolpkg.py . artifacts/com.nyan.turn_guard-0.8.0.toolpkg
```

**注意两件事**：

1. `src/ui/settings/index.ui.js` 是**手写**的 Compose DSL 页面，不经过 tsc 编译。改动后要同步复制到 `dist/ui/settings/index.ui.js`，打包取的是 dist 那份。
2. `dist/` 已随仓库提供（省得别人先装 TypeScript 才能打包），但它**是构建产物**：改了 `src/*.ts` 必须重新 `tsc`，否则产物与源码不一致。

### 目录结构

```
manifest.json          包清单（toolpkg_id / version / display_name）
tsconfig.json          TS 编译配置
src/guard.ts           判定核心（纯逻辑，可脱离 Operit 单测）
src/main.ts            钩子与 UI 注册入口
src/tools.ts           两个工具：turn_guard_status / turn_guard_config
src/ui/settings/       设置页（手写 Compose DSL）
dist/                  构建产物
test/                  七套零依赖单测
tools/pack_toolpkg.py  打包脚本
```

## 已知限制

- **做不到强制结束回合**。Operit 的 prompt 钩子只能改提示内容，没有 stop/abort。所以守卫能做的上限是「封工具 + 喊收尾」，最终交不交付仍取决于模型本身。
- **配置与状态工具豁免**，硬拦后仍可读取状态或修改配置；普通工具仍受预算限制。
- **单计数器**。切换会话会清零本轮计数，所以它衡量的是「当前这一轮」，不是跨会话的长期统计。
- **不统计工具内部的嵌套调用**，只数模型直接发起的调用。
- **常驻规则的加载条件**：0.9.0 起由插件注册的 `systemPromptCompose` 钩子写入，**不再需要 `use_package` 激活**（已实测）；角色卡 `allowedPackages` 是否为前置条件未单独 A/B（本机始终处于绑定状态）。
- **轮次边界靠 sender 推断**：`sender` 是字符串不是枚举，遇到未知值只记录不猜。

- **0.8.2**：轮次边界改为监听 `message_persisted` 按 sender 清零——用户消息开新轮、AI 回复算本轮达成；`lastSender` 进 status。
