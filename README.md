# 灯火阑珊 · Lamplight

> 给 AI 的单轮任务装一道收敛闸：该提醒时把话说进它眼前，该拦住时直接拦下，并明确告诉它「现在该交付什么」。

名字取自「蓦然回首，那人却在灯火阑珊处」——热闹（疯狂调工具）散去的地方，才看得见人。硬拦发生后，AI 停下工具调用，回头把进度说清楚，而不是继续往前冲。

这是一个 [Operit](https://github.com/fengyu-12) 的 ToolPkg 插件，包 ID `com.nyan.turn_guard`。

---

## 它解决什么

AI 干长活会跑偏：同一个工具反复调、同一个错反复撞、一轮几十次调用还在原地打转。
本插件挂在工具生命周期钩子上做计数与判定，用八个可调阈值把「继续尝试」和「该收尾了」分开。

| 信号 | 默认值 | 触发后 |
|---|---|---|
| 调用次数 | 8 次 | **拦下当次调用**，送达一句提醒，随后放行 |
| 提醒时长 | 本轮 5 分钟 | 同上 |
| 连续硬失败 | 3 次 | 同上 |
| 相同调用 | 同工具同参数连续 3 次 | **拒绝本次调用**，并给出收尾指令 |
| 硬阈值 | 50 次调用 | **拒绝后续调用**，并给出收尾指令 |
| 硬停时长 | 15 分钟 | 同上 |
| 空闲重置 | 80 秒 | 无工具在途且静默超过该时长，仅清调用计数 |
| 活动断档 | 10 分钟 | 无工具在途且静默超过上两者较大值，重开活动轮次 |

判定分两层：**软阈值只提醒**（拦一次、送达、放行、不锁轮），**硬阈值按停**（拒绝调用、锁住本轮）。

### 三条软提醒

三路信号共用同一句结尾：**说一句用户可见的进度，然后继续**。

| 类型 | 原文 |
|---|---|
| 调用较多 | `【软提醒 · 灯火阑珊】本轮已连续调用工具 N 次（阈值 M）。本次调用被拦下仅用于提醒，不是错误、不计失败。请先用一句用户可见的话说明当前进度（已确认什么 / 还在查什么），然后继续原任务；后续调用正常放行，不会再被这条提醒拦截。` |
| 本轮耗时较久 | 同上，抬头换成 `本轮已连续运行 X 分钟（阈值 Y 分钟）` |
| 连续硬失败 | `【软提醒 · 灯火阑珊】检测到连续硬失败 N 次（超时 / 权限 / 参数 / 执行异常）。本次调用被拦下仅用于提醒，不是新的错误。请先报告失败原因与已试路径，再决定是否换一次实质不同的做法；后续调用正常放行。` |

为什么提醒要「拦一下」：Operit 2.0.0 只保证把文本送到模型眼前的通道是 `tool_call_intercept` 阶段返回的 `block.reason`——提示词注入、system prompt 改写、工具清单改写实测全部会被丢弃。所以提醒**借一次拦截换它看一眼**：被拦那次工具不执行，提醒送达后放行；每轮最多拦一次；被拦那次仍算一次调用，但**不计入硬阈值预算、不计入硬失败链**。

## 常驻收敛规则（system prompt 层）

规则直接拼进 **system prompt**，每一次模型请求都带着，**不需要在会话里激活插件**。

它是**固定的定性文案，不含任何阈值数字**——所以把阈值从 8 改成 15，system prompt 一个字节都不变，不会让上下文缓存失效（改一次阈值触发一次全量重算，实测能到几十万 token）。

```text
【收敛规则 · 灯火阑珊】
交付前先说明：已确认什么、还缺什么。
连续工具调用较多或本轮耗时较久时，先给用户一句当前进度再继续原任务。
连续硬失败时，先向用户说明失败原因与已试过的做法，再决定是否换一次实质不同的做法。
同一工具同一参数反复调用视为原地打转，启用硬拦截时会按阻塞处理。
启用硬拦截且达到调用或时长上限时，工具调用会被拒绝；请直接收尾并说明已验证结果、未完成项、阻塞与可行下一步。
触发式软提醒仅用于提醒，不是错误；先报告进度，然后继续原任务，后续调用正常放行。
具体阈值与开关见「灯火阑珊设置」。
用户发来新消息即视为新一轮，重新计数。
【收敛规则结束 · 灯火阑珊】
```

三个开关互相独立：常驻收敛规则（默认开）、接近阈值时提醒（默认开）、达到上限时拦截（默认开）。

## 拦住之后还给一条收尾指令

硬拦的 `reason` 本身就是收尾要求，AI 一定会读到：

> `重复调用 / 超出单轮工具调用预算 / 超出单轮时间预算，本次调用已拦截。请立即用一条用户可见回复说明：① 已验证结果 ② 未完成项 ③ 阻塞 ④ 可行下一步。不要再调用工具，不得伪称完成。`

## 一轮怎么算

- **计数窗口**按事件间隔算，静默超过「空闲重置」就清零。
- **活动计时**用独立起点 `activeSince`，从本轮首个事件起算，只有静默超过「活动断档（10 分钟）」才重开。
- **有工具在途时不判重置**，长工具跑完不会被当成本轮结束。
- **用户发新消息即新一轮**，计数与提醒额度一起重置（按消息发送者判定，机器人回自己的话不算）。

## 已知限制

- **做不到强制结束回合**。守卫能做的是「封工具 + 喊收尾」，最终交不交付仍取决于模型本身。
- **软提醒拦得住工具，拦不住决心**。它保证那句话送到模型眼前，但模型是否照做仍看它自己。
- **「相同失败」开关暂不支持**（`errRepeatLimit`）：宿主不提供可识别的同参重复失败事件，设定页已用灰字标注，它永不触发。按失败收敛请用「连续硬失败」。
- **硬失败的实际覆盖范围**：权限拒绝、参数非法、执行异常能计入；**超时目前计入不了**（`bash` 的前台超时是把命令转后台，对宿主不算失败）。
- **硬拦自身产生的 tool error 会被计入硬失败链**（已知缺陷，待修）。
- **拦截期间配置工具仍可用**：`turn_guard_config` / `turn_guard_status` 是白名单豁免的。
- **计数按会话分开**；不统计工具内部的嵌套调用。

## 安装

1. 下载 `artifacts/com.nyan.turn_guard-0.9.15.toolpkg`
2. 在 Operit 里导入并启用；装好后到「灯火阑珊设置」确认阈值
3. 换版时必须**沿用原文件名**并清掉解包缓存，否则宿主按签名判定「无变化」不会重载

## 开发与构建

```bash
npm test                      # 七套回归（0.4 / 0.5 / 0.6 / 0.6.2 / 0.6.6 / 0.7 / 0.8）
node test/test-v0.9.15-gate.cjs   # 0.9.15 的 T20/T21/T19 门禁（由交付方提供，未入库）
python3 tools/pack_toolpkg.py . artifacts/com.nyan.turn_guard-<version>.toolpkg
```

> ⚠️ **本仓库当前的 `src/` 是 0.9.3 的 TypeScript 源码，而 `dist/` 已是 0.9.15 的编译产物。**
> 0.9.13 / 0.9.15 两轮改动直接落在 `dist/*.js` 上（当事人环境没有可用的 `tsc`）。
> 因此**不要直接 `npm run build`**——那会把 `dist/` 覆盖回 0.9.3。
> 需要改代码时：先按 `dist/guard.js` 的现状反推回 `src/guard.ts`，再重新编译并逐字节比对。
